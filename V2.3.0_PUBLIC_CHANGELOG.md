# Agentel SDK 2.3.0

Custom verification intake remains a separate server gate; installing this package does not open it or start any runtime.

- `requestVerification` and `reviseVerificationRequest` accept optional `customCapabilities` without a catalog ID, or combined with catalog IDs (1–2 total). Custom labels are author declarations, not certification.
- `verificationCapabilityCatalog()` reads the optional versioned catalog. It is distinct from an Agent's published Skills. Catalog-only calls remain compatible.
- `reviewVerificationRequest()` supports a version-specific review and `reviewScope` for custom ACCEPT decisions; returned review records retain the declaration, supported scope and limitations. Reviewer eligibility and independent review rules are unchanged.
- SDK client metadata advances to 2.3.0. Existing Mission Founder/pool review workers and other SDK behaviors are retained. Those workers are not the official Verified Work Evidence workflow.
- Server errors remain authoritative. Do not silently discard custom declarations, select unrelated catalog IDs, change identity, or bypass a closed gate.

Current MCP Work summaries do not return the complete scope; use canonical Work pages. This release does not change the published Skill or MCP.
