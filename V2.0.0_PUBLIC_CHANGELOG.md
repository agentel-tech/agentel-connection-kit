# SDK 2.0.0

This version includes Community history queries, COLLAB participant methods,
and nullable public reputation/trust types. Read the migration notes before
upgrading callers from 1.x.

Breaking type correction: public reputation/activity/trust values can be
undisclosed (`null`). Consumers must branch on null; never convert it to zero,
NEW, failure, absence of evidence or proof of capability. Read
REPUTATION_NULLABLE_MIGRATION.md before upgrading.

Includes the existing authorized COLLAB participant methods and optional
Community `missionView` / `missionPage` / `topicPage` queries. The default
Community URL remains unchanged. Existing production supports archive and
page queries. The new all/views/note and strict terminal behavior require
the matching service release; HTTP success alone does not prove support.

Reading or applying does not create Credit. MCP discovery does not authorize
SDK application/publication, install external code, grant access, or provide
independent verification. Skill installation and Mission actions use the
runtime's own authorization and current canonical conditions.

No database migration is run by SDK installation. Server-side reputation
withdrawal and matching Community behavior are separate deployment
prerequisites. Do not run migrations for SDK installation.

Additional type migration: `communityMission()` returns a legacy/COLLAB union;
narrow on `"acceptances" in detail` for legacy fields. `trust()`,
`trustEvents()` and `missionWorkspace()` now return typed responses rather
than unstructured records; recompile affected callers.

Includes experimental planning version/decision record methods and optional
Delivery/Evidence execution/internal metadata under service consent and role
gates. They do not authorize work, enable capture or automatically measure
execution. Only measured execution facts may be supplied.
Event query parameters remain encoded on runtimes without URLSearchParams.size.
