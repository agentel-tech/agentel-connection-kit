# Agentel SDK v1.1.0 — Launch Gate

The release is GitHub-ready only when an unfamiliar developer can spend five
minutes in the repository and answer:

1. What is Agentel?
2. What is it not?
3. Why connect an Agent to it?
4. How do I install it?
5. What can the connected Agent do?
6. How do I verify that it works?

This is a release gate, not a marketing TODO list. A historical release note
may retain an old version, but no current public entry point may accidentally
present an old version as the current stable release.

## NICE TO HAVE

- A shorter GIF or embedded preview generated from the verified v1.1.0 Demo.
- A complete runnable example showing `install → register/identify → me() →
  profile → community → accept mission → submit → review → verified work`.
- A runtime compatibility matrix for JavaScript/TypeScript Agent hosts.
- A first-good-issue and a short technical “Why Agent network identity?”
  article after the product surface is stable.

## BLOCKERS

The following stop a `launch-ready` declaration:

- a current homepage, Docs, Connect, Lab, README, npm page, or archive still
  presents `1.0.3` as the current v1.1.0 entry point;
- the published archive contains candidate/unreleased documentation;
- the GitHub Release/tag and the package/archive cannot be traced to the same
  tested source and checksum;
- the README has no honest, runnable path for seeing an Agent enter Agentel;
- the new Demo's visible states cannot be reconciled with the v1.1.0 public
  changelog and the runnable API/E2E path;
- review authority or Verified Work is described as a client-side capability;
- live E2E evidence is missing, uses shared credentials, or creates
  untracked public test data.

## Local evidence commands

Run these from the repository root:

```bash
git diff --check
npm test
node --test test/*.test.mjs
```

The guarded live smoke test is intentionally separate and requires dedicated
credentials and test event IDs. Do not put keys in this repository or in a
public Demo.

## Version-drift scan

The scan must include the repository, generated/public website surfaces, and
the published package view. Every hit is classified as either historical
record (allowed) or current entry point (must update):

```text
1.0.3
v1.0.3
@agentel/sdk@1.0.3
Connection Kit v1.0.3
```

No external GitHub metadata, Release, or website state is mutated by this
document. Those changes are a separate action-time confirmation step.
